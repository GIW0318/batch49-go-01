# 高基数限流键的分片滑动窗口与折叠

## 题面

按租户和资源类型打键的限流上线后，网关内存一路涨到 OOM：键的基数比预估高了两个数量级，分片表无上限地膨胀，冷掉的键永远不回收；同一批请求在窗口边界前后各扣一次，本来只有八次用量，账上却记成十二次，正常业务被误限；扩容分片之后，那些被折叠到父键的子键配额又从零开始算，父键额度被放大了一倍，等于给大户开了后门。

改动落在模块 gsb/batch49-go-safety-b-04 的 rate_key_shard.go，类型 ShardLimiter 负责键的分片计数、折叠与冷键淘汰。核心签名保持：NewShardLimiter(cfg LimiterConfig) *ShardLimiter、Allow(key string, cost int) (Decision, error)、Fold(keys []string, parent string) error、Usage(key string) Usage、ParentOf(key string) (string, bool)、ShardCount() int、Keys() []string、Sweep() int、Reset(key string)、Limit() int、Snapshot() ([]byte, error)、Restore([]byte) error。

需要落地的行为如下。

一、窗口按时间戳滑动：只统计时刻晚于当前时刻减去窗口宽度的用量，正好落在窗口左边界上的记录要算过期。

二、允许时返回本次扣减后的用量与剩余额度；用量加上本次开销会越过上限时拒绝，并在结论里给出越界原因，被拒的开销不得记账。

三、单次开销大于上限时直接拒绝并给出独立原因码，且不分配分片；开销为零或为负报 ErrBadCost，空键报 ErrBlankKey。

四、空键、坏开销这类非法入参不得改动分片表，Sweep 与 Usage 读取未出现过的键同样不得分配分片。

五、折叠把一组子键路由到父键，子键此后的扣减全部记在父键窗口上；父键的上限不因为折叠了多个子键而放大。

六、折叠要把子键的历史用量并进父键，父键从已有用量继续累计，不得从零重新计数。

七、父键自身带着折叠集合的计数，Usage 要能读出被折叠的子键个数；子键的 Usage 要标出已折叠与父键名。

八、空父键报 ErrBlankKey；把键折进自己、或把父键折进它自己的子键都要报 ErrFoldCycle，且拒绝后原有折叠关系保持不变。

九、分片表受预算约束，新增键会超出预算时按预设规则把部分子键折叠到配置的溢出父键，折叠后分片数不得超过预算。

十、冷键按空闲时间淘汰，Sweep 返回被淘汰的键数；未到阈值的键不得被淘汰，空表上再扫一次返回零。

十一、Reset 只清指定键的窗口，不影响其它键；对不存在的键 Reset 是空操作。

十二、快照要覆盖分片表、每个键的时间戳用量与折叠映射；损坏或空快照报 ErrBadSnapshot，且不影响在线窗口。

硬约束：同一键的扣减必须串行，并发扣减时准入总数不得超过上限，也不得因为并发把同一笔开销记两次；进程重启后各键的窗口与折叠关系要原样恢复，恢复后继续扣减要接着原有用量算，不得重置；分片表与折叠集合的增长受预算硬顶，不能靠淘汰已有键来腾位置。
