## 题面

公会赛季结算当天，贡献榜前十的成员里有三个被降成学徒，翻记录发现他们整周都在打本；刚入会两天的新人因为活跃不足被整周扣减，退会再回来的老成员却保留着原来的在职时长，晋升判定直接通过。问题落在 gsb/batch49-go-game-a-29 的 guild_standing_ledger.go，请补齐 StandingLedger 的贡献、晋升与周衰减行为。

接口：NewStandingLedger(Options) *StandingLedger；AddMember(string, string, int64) error；Leave(string, string) error；Contribute(string, string, string, string, int64, int64) error；Promote(string, string, int64) (RankChange, error)；WeeklyDecay(string, int64) ([]RankChange, error)；Standing(string, string) Standing；Members(string) []Standing；Guild(string) (Guild, bool)；Ranks() []RankRule；Snapshot() ([]byte, error)；Restore([]byte) error。

需要落地的规则共十二条：（1）职级表至少两档，名称非空且互不重复，首档累计贡献门槛为零，贡献门槛与在职时长门槛都逐级递增，非法职级表拒绝装载。（2）入会要求公会标识与成员标识非空、入会时刻为正；空公会的第一个成员直接成为最高职位，其余成员从最低档开始，重复入会与超过人数上限都要报错。（3）贡献按活动类型系数折算，折算结果为数量乘系数再除以一百并向下取整，未知类型、数量非正、事件编号为空、时刻非正一律拒绝且不落账。（4）同一公会内事件编号幂等，同一编号重复提交直接成功返回，金额与类型都按首次为准。（5）累计贡献与在职时长由账户状态汇总，成员列表按成员标识升序返回，职级表查询返回副本。（6）晋升要求累计贡献与在职时长同时达到下一档门槛，在职时长按当前时刻减入会时刻计算；每次调用最多升一档，到顶返回 max_rank，条件不足返回 not_eligible 且职位不变。（7）周衰减按周关闭：本周活跃低于下限时，先把此前各周贡献按衰减比例向下取整，再叠加本周贡献；周衰减与本周贡献同时存在时顺序不能反，否则活跃玩家会被误降。（8）衰减后累计贡献低于当前职位门槛时降一档，每次最多降一档；最低档不再降。（9）最高职位不参与衰减与降级，其贡献原样保留。（10）本周中途入会、在会时间不足整周的成员，活跃下限按实际在会秒数占整周的比例折算后再比较，不得整周扣减。（11）退会移除成员及其贡献，之后再用同一标识入会属于全新成员，在职时长从新的入会时刻重新计算，旧贡献不保留。（12）快照保存公会、成员、分周贡献、职位与事件去重索引，恢复要么整体替换要么原样不动，非法载荷报错。

硬约束：同一公会的入会、贡献、晋升与周衰减必须串行，多协程同时写入不能丢贡献、不能出现半更新的职级；快照与结算并发时只能看到完整状态，重启后从快照恢复的累计贡献、分周桶、职位和去重索引要逐字段还原。

验收：go test ./... 十五条全部通过；不得修改测试、跳过用例或按固定成员写死结果；并发与重启后的行为自行补充验证；只在本地实现，不接入外部服务。
