取证台上周的批量排查出了岔子：同一份主机证据被两条规则各自判成了一起事件，值班同学按发现编号追链条，点开却只有一句“命中”，既看不到哪条规则靠哪些证据推出，也说不清另一条规则为何被吞。更麻烦的是，有一次扫描在轮次用尽后把没跑完的规则算成命中，报表里多出一批告警；还有一次，某台机器把邻机主体写进了自己的证据库，第二天复扫两边结论互相污染。落点 gsb/batch49-go-safety-c-01 的 evidence_chain_rule_engine.go，类型 EvidenceRuleEngine，签名保持：NewEvidenceRuleEngine() *EvidenceRuleEngine、Register(rule Rule) error、Rules() []string、Run(target Target, budget Budget) (Result, error)、Findings(targetID string) []Finding、Evidence(targetID string) []EvidenceItem、Explain(findingID string) (Chain, error)、LastResult(targetID string) (Result, bool)、Incomplete(targetID string) []string、Reset(targetID string) error、Snapshot() ([]byte, error)、Restore(data []byte) error。

要修：规则必须声明至少一条产出证据，只声明消耗的规则在注册期就报 ErrBadRule；规则编号为空报 ErrBlankRuleID，重复编号报 ErrDuplicateRule，规则之间的依赖图成环——包括一条规则要求自己产出的证据——一律报 ErrRuleCycle，被拒的规则不得留在注册表里；Rules() 按注册先后返回。求值按轮推进，每轮只对前置证据齐备、且本目标上未触发过的规则求值，同一规则对同一目标至多触发一次；一条规则产出的证据进入证据库后，下一轮才允许被别的规则消费，所以两级级联必须落在两个不同轮次上。产出的证据按种类与主体联合键去重，同一条证据被多条规则产出时库里只保留最先落库的那条；与此同时，每个产出者都要能在来源链里查到，不能只留一个匿名的结果，发现的 subject 取该规则首个产出证据的主体，收敛后 Converged 置真。每条发现要能按编号回溯到产出它的规则以及它依赖的每一条证据及其产出规则与轮次，编号不存在或为空报 ErrUnknownFinding。预算必须为正，轮数或发现上限非正报 ErrBadBudget；发现条数达到上限立即截断并置 Truncated，不再触发后续规则。轮次上限到达时仍未满足前置条件的规则，要在结果里标成未完成，不得凭部分证据判成命中。证据主体必须落在当前目标的主体集合内，规则若产出目标之外的主体，整次求值直接拒绝并报 ErrForeignSubject，不能留下半截证据。不同目标的证据库与发现互相隔离，对同一目标重复求值是增量的：已经触发过的规则不再重复出发现，也不会重复堆证据，Reset 清空该目标的证据与发现但保留规则注册表。同一时刻只允许一次求值，撞上正在进行的求值直接报 ErrRunBusy，不得交叉写入；快照要连同规则、各目标证据、发现与回溯链一起序列化，恢复后再求值、再解释都必须接着原状态走；损坏的快照报 ErrBadSnapshot 且不得改动现网状态。

硬约束：并发求值必须串行裁决，被拒的调用不得留下任何证据或发现；快照只能看到全量旧状态或全量新状态，恢复是全有或全无；单次求值的证据量受发现上限与轮数上限双重钳制，不能无限增长。
