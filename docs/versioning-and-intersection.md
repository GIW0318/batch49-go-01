# 版本与求交口径说明

## 求交口径

- 作用域统一写作 `resource:action`，恰好一个冒号且两段均非空，否则报 `ErrBadScope`。
- 一个请求 `(resource, action)` 放行的充要条件：`resource:action` 同时出现在
  key 当前存储的作用域集合与所有者**当前**权限集合中（两者求交）。
- 放行判定原因码 `scope_ok`，任一侧缺失即拒绝并给 `scope_missing`；判定同时携带
  读取时刻的 key 版本号与当前优先级。
- 所有者权限被 `SetOwnerPermissions` 收回后，求交结果立即收窄——有效作用域永远
  以"请求时刻"的所有者权限为准，不沿用签发时固化的集合。
- `Impact` 与 `Reconcile` 只读：按同一求交口径预演会失去（Lost）与仍保留（Kept）
  的作用域，不改 key、不推进版本；同一状态下反复生成内容一致（条目按 key 排序、
  列表按字典序）。
- `Apply` 落地时不照搬报告：按**应用时刻**的所有者最新权限重新求交得到后值，
  再写入 key 并推进版本。报告生成到应用之间权限再次变化的，以应用时刻为准。

## 版本口径

- 新登记的 key 版本为 1；每次 `Apply` 成功版本加一，作用域整体替换为差异后值。
- `Reconcile` 生成的差异记录基准版本；`Apply` 时若 key 当前版本已不等于差异基准
  版本，报 `ErrDiffStale` 拒绝。同一 key 的并发 `Apply` 因此只有一个能成功，
  后到者按版本冲突拒绝。
- 读一致性：版本号与作用域集合在同一把锁内读取，永远来自同一份快照，不会出现
  一半新一半旧。`Authorize` 在判定落地前复核版本号，若期间发生了收窄则按新版本
  重算，保证在途请求不会沿用旧版本的判定结果。
- 重算与请求并发时，版本号较大者即较新状态；读者要么看到收窄前完整快照，要么看到
  收窄后完整快照。

## 快照与恢复

- `Snapshot` 整份序列化所有者权限表、key 表（作用域、版本、优先级）与差异计数器。
- `Restore` 先完整解码并校验（格式版本、作用域写法、版本非零、优先级 0–5、
  所有者引用存在、key 无重复），任一失败报 `ErrBadSnapshot` 且现有状态原样保留；
  校验通过才整体换入。重启恢复后版本号延续，差异标识不与恢复前冲突。

## 上限口径

- `MaxKeysPerOwner` 是硬上限：达到上限后新登记直接报 `ErrKeyLimit`，不淘汰旧 key。
- `MaxScopesPerKey` 对去重后的作用域条目数生效，超限报 `ErrScopeLimit`。
- 上限值小于等于 0 视为不限制。
