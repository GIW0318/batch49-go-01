## 题面

客服接到一批私聊记录缺失的工单：玩家换了手机之后，旧设备上看过的消息在新设备上补不回来；另一些会话被折叠成空白，重连时只补发了后半段，前面对话像是没发生过。问题落在 gsb/batch49-go-game-a-30 的 dm_read_cursor.go，请补齐 DmCursorStore 的留存、已读游标与补发行为。

接口：NewDmCursorStore(Options) *DmCursorStore；Send(string, string, string, int64) (Message, error)；Fetch(string, string, int64) []Message；Ack(string, string, string, int64) error；Cursor(string, string) int64；Prune(int64) (int, error)；Conversation(string, string) (Conversation, bool)；Conversations(string) []Conversation；Devices(string, string) []DeviceCursor；Snapshot() ([]byte, error)；Restore([]byte) error。

需要落地的规则共十二条：（1）会话按参与者双方归一，两个方向共用一条序号序列，序号从一开计且严格递增，双方查询看到同一条时间线。（2）发送要求双方标识非空、内容去空白后非空、双方不相同、时刻为正，非法发送不得建会话也不得占用序号。（3）补拉按会话内序号取大于入参的全部消息，按序号升序返回副本，双方视角一致。（4）确认按账号、设备、会话三者组合记录，序号不得为负；会话不存在时拒绝确认。（5）确认只前进，同一设备重复确认同一序号幂等成功，不得因为非前进而报错，也不得让游标倒退。（6）会话级游标取该会话各设备已确认序号的最小值，没有设备确认过时为零；已下发不等于已读，补拉动作不能抬高游标。（7）会话视图带最近序号、当前保留条数、截断标记与合并游标；账号的会话列表按对方标识升序。（8）会话保留条数超过上限时淘汰最旧消息，截断标记置位，游标不因淘汰而回退。（9）按时间清理只删除时刻不晚于当前时刻减保留时长的消息，返回删除条数，时刻非正报错，清理同样会置位截断标记。（10）设备列表按设备标识升序返回副本，调用方修改返回值不得影响内部记录。（11）会话列表与会话视图对未知账号或未知会话返回不可用，不凭空创建状态。（12）快照保存消息、各端游标、截断标记与下一条序号，恢复要么整体替换要么原样不动，非法载荷报错，恢复后继续发送的序号必须接着走。

硬约束：同一会话的发送必须串行，多协程同时发送不得出现重复序号或丢消息；确认与补拉并发时只能看到完整的消息链和游标，重启后从快照恢复的设备游标、截断标记与序号水位要逐字段还原。
